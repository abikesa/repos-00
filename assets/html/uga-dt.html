01 · The problem

You fly blind before Cabinet.

The challenge isn't a lack of data. Uganda has enormous reporting infrastructure. The challenge is decision latency — when a Cabinet summons arrives at short notice, the best available intelligence is a static PDF from the previous fiscal year.

"We usually have to fly blind. We no longer have access to the infrastructure we commissioned."

Data is fragmented · Reports are retrospective · No live query layer · Decision latency kills policy quality

02 · Core concept

A simulation dies.
A twin lives.

A simulation is a snapshot. It reflects the world at the moment it was built — then it goes stale. A digital twin is continuously synchronized with reality through automated data pipelines. It never goes stale because it never stops updating.

The key innovation: an LLM as the interface layer. No dashboard training. No complex filters. You type a question; the twin answers it.

QUERY EXAMPLE

04 · API endpoints · for Vincent's team

What the backend actually does.

endpoint what it does technical note
GET /districts Returns all 135 districts with mh, mort, mal, so values Lazily initializes synthetic state on first call via random.seed(42)
GET /compute Recomputes loss for every district Weighted composite: L = 0.35·mh + 0.25·mort + 0.25·mal + 0.15·so
POST /intervene Applies a resource intervention to a named district — mutates state Differential reduction rates per indicator — malaria most sensitive (1.2×), social outcomes least (0.5×)
POST /whatif Same as /intervene but does not mutate state — pure preview Returns a deep copy via model_copy(deep=True) — safe for Cabinet scenarios
POST /bayesian-swap Fuses two districts' data into a shared posterior Simple mean fusion — placeholder for real Bayesian update when real data arrives; source tag flips to "bayesian"

05 · The loss function · why the heatmap is not decoration

The map is
the math.

L(θ) = 0.35·mh + 0.25·mort + 0.25·mal + 0.15·so
mh = mental health burden
mort = under-5 mortality rate
mal = malaria incidence
so = social outcomes index

Each district gets a score between 0–1. The heatmap renders that score as colour. Red = L(θ) near 1 = maximum gap to NDP target. Violet = L(θ) near 0 = optimized.

06 · Synthetic → real · the Bayesian rehearsal

You don't need clean data to start.
You need the pipeline.

In clinical research we run power calculations and simulate the data before a single patient is enrolled. We rehearse the infrastructure before reality arrives. Same methodology here.

PHASE 1 · SYNTHETIC
State seeded from geographic priors · source: "synthetic" · District officers onboard · Infrastructure rehearsed · Decision loop practiced
↓
PHASE 2 · HYBRID
Real uploads arrive · /bayesian-swap fuses priors with observations · source tag flips: "synthetic" → "real" · Confidence weights update
↓
PHASE 3 · LIVE
All 135 districts reporting · Automatic daily update cycle · NPA queries the twin in natural language · Cabinet briefs generated on demand

THIS IS HOW ALPHAFOLD WORKED

AlphaFold trained on structural priors before experimental data. Autonomous vehicles train in simulation before roads. The digital twin starts in synthetic phase so you can rehearse the rhythm of governance before stakes are real.

09 · Anticipated objections · hold your ground

They will test you.
Be ready.

"Does this replace our jobs?"

No — your role shifts from data entry and cleaning to system oversight. The pipeline handles the mechanical work. You manage the tokens, validate anomalies, and run the what-if scenarios. You become the operators of a national intelligence system, not spreadsheet cleaners.

"Why FastAPI and not something enterprise — Oracle, SAP?"

FastAPI is the standard for high-performance Python APIs — used at Netflix, Microsoft, Uber. It's stateless, horizontally scalable, and the ecosystem runs on open standards. Enterprise stacks lock you into vendor contracts. This stack can be containerized and hosted on NPA's own servers if needed — no lock-in.

"The state is in-memory — what happens if the server restarts?"

Good catch. Current demo uses in-memory state for speed — standard for PoC. Production version persists to PostgreSQL or MongoDB with generate_synthetic() as fallback. The source field tracks whether each district's data is synthetic, real, or bayesian-fused, so you always know data provenance.

"What about data sovereignty? Who owns the data?"

NPA owns all data submitted through the pipeline. Ukubona LLC owns the model, the heatmap frontend, and the inference layer. Data never leaves Uganda's jurisdictional scope in production — we can host on NITA-U infrastructure or any cloud provider NPA designates.
